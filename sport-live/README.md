# sport-live/ — прототип sportsbook-iframe на живом фиде (дизайн 01 «Пижама»)

Контент, который партнёр встраивает к себе `<iframe>`: главная (виды спорта,
Hot events, LIVE-таблица, расписание, купон) и страница события со всеми
маркетами. Дизайн — один в один мок `sportsbook-iframe-designs/designs/01-pyzhama-original`
(палитра gameportal, Poppins, та же разметка и CSS), данные — живой фид.
Живёт на тест-сервере: `https://gem.x1b.site/sport-live/`
(`event.html?id=<feed_id>` — событие, `?user=<id>` — пользователь кошелька,
по умолчанию `42`). Шапка без навигации портала: логотип, LED «Live»
(состояние подключения к WS-серверу: серый мигающий — подключение, зелёный —
подключён, красный — нет связи) и баланс эмулированного кошелька партнёра.
Ставки принимаются в эмулированный кошелёк (см. ниже), реального бэкенда
ставок нет.

## Как устроено

```
sport-live/
├── index.html            ← лайв: шапка, сайдбар, hot и таблица live (разметка desktop.html мока)
├── line.html             ← линия (prematch): та же разметка, вместо live — расписание
├── event.html            ← разметка event.html мока (шапка события, маркеты, купон)
├── api/wallet.php        ← эмуляция кошелька партнёра: балансы и ставки в текстовом JSON
├── sport-live.nginx.conf ← location /sport-live/ (статика + PHP-FPM для api/*.php)
└── assets/
    ├── css/main.css      ← CSS мока + подсветка изменения кэфа, счёт по периодам, LED «Live»
    └── js/
        ├── live-data.js  ← адаптер: строит window.SB (контракт мока) из живых данных + клиент кошелька
        └── main.js       ← движок рендера мока с минимальными правками под живые данные
```

## Кошелёк партнёра (эмуляция) и ставки

Та же максимально простая схема, что у тестового стенда Borlette
(`https://gem.x1b.site/`, `platform/v3/index.php`): никакой БД, балансы в
текстовом файле `/var/lib/sport-live/wallet.json` (`{balances, processed,
bets}`), стартовый баланс 10 000 HTG (хранится в сантимах), дедупликация по
`receipt_id`, журнал `wallet.log` рядом. Эндпоинт `api/wallet.php` (PHP-FPM,
запись под `flock`):

| Вызов | Что делает |
|---|---|
| `?action=get_balance&user=42` | баланс пользователя (создаёт со стартовыми 10 000 HTG) |
| `?action=bets&user=42` | баланс + последние 50 ставок пользователя |
| `POST {action:"place_bet", user, receipt_id, stake, selections:[{ev,mk,oc,odds,label,event,market}]}` | списание ставки (купон = экспресс), запись ставки `status: open`; `No enough money` при нехватке. **Задержка приёма 3 с** (`BET_DELAY_MS`, как у букмекеров): запрос держится 3 секунды, файл кошелька на это время отпускается; затем кэфы и доступность каждого исхода сверяются с `feed_bridge` (пользователь БД `sport_ro`): кэф упал хотя бы по одной ноге → `{error:"odds_changed", changes:[{ev,mk,oc,odds_old,odds_new}]}`, кэф только вырос → ставка принимается по новым, большим кэфам без подтверждения (в ответе `improved`), исход закрыт или рассчитан → `{error:"unavailable"}`. На странице во время задержки на кнопке обратный отсчёт, купон заблокирован; при `odds_changed` кэфы в купоне обновляются, появляется предупреждение и кнопка «Подтвердить ставку» — новый цикл приёма |
| `POST {action:"cancel_bet", user, receipt_id}` | возврат открытой ставки |
| `POST {action:"hide_bet", user, bet_id}` | убрать рассчитанную ставку из «Моих ставок» (корзина в левом нижнем углу карточки; запись остаётся в файле с `hidden: true`, открытую ставку убрать нельзя) |
| `?action=cashout_check&user=42&bet_id=…` | котировка кешаута открытой ставки: `{enabled, price, ratio, delay_ms, reason}` |
| `POST {action:"cashout", user, bet_id}` | выкуп открытой ставки (кешаут): запрос держится 5 с (`CASHOUT_DELAY_MS`), затем котировка считается заново и выплачивается по ней; ставка получает `status: cashout`, `payout` = сумма выкупа, запись `bet.cashout {ratio, actual, percent, quoted}`; `{error:"cashout_unavailable", reason}`, если выкуп недоступен; дедуп по `bet_id` |

### Гейт свежести фида

Приём ставки и выкуп разрешены только когда мост сообщает состояние `OPEN`.
Состояние пишет сам мост (`feedbridge/gate.py`) в `/var/lib/feed-health/gate.json`
раз в несколько секунд; `wallet.php` читает файл на каждом денежном вызове.
Отказ — `{result:false, error:"feed_suspended", gate:{state, reasons, lag, age}}`.

Закрытым считается всё, кроме `OPEN`: состояние `HOLD` (сигналы в норме, но
выдержка после сбоя ещё не выдержана), `SUSPEND`, отсутствующий файл и файл
старше `GATE_MAX_AGE` (30 с) — молчание моста не повод считать линию свежей.

Проверка стоит в четырёх точках: у приёма ставки — до трёхсекундной задержки
(чтобы не держать пользователя зря) и после неё (решающая: именно по цене этого
момента ставка и принимается); у кешаута — так же, до и после пятисекундной
паузы выкупа. Состояние гейта уходит и в ответы `get_balance`/`bets`, поэтому
страница гасит кнопку «Сделать ставку» и показывает предупреждение заранее,
не дожидаясь отказа.

Зачем: 12.09.2026 мост отставал от фида на 40–50 минут, гейт корректно стоял в
`SUSPEND` два с половиной часа, но его никто не спрашивал — ставки принимались по
устаревшим коэффициентам. Гейт был индикацией для витрины здоровья; теперь это
запрет. Причина отставания устранена отдельно (пакетная запись в MySQL,
`feedbridge/batch.py`).

**Расчёт и начисление выигрыша** — сборщик `health/collect.py` раз в минуту
(`settle_bets`): для открытых ставок смотрит исходы в `feed_bridge.outcomes`
(`status 4` = рассчитан; `result` 1 win, 2 loss, 3 return, 4/5 half win/loss;
`cancelled` = возврат). Любая проигравшая нога → `lose` сразу; когда все ноги
рассчитаны → выплата `stake × произведение кэфов` (возвратная нога = кэф 1),
статус `win` или `return`, сумма добавляется к балансу в том же файле под тем
же `flock`. Исход, пропавший из БД (событие зачищено ретенцией), через 7 суток
считается возвратом. Страница опрашивает кошелёк каждые 30 с: баланс в шапке
подсвечивается при изменении, по рассчитанным ставкам показывается тост.

**Кешаут (выкуп ставки)** — логика и лимиты взяты из бэка Спорта
(`betting/BackEnd`: `Model\Bet::calc_cashout_ratio`, `cashout_enabled`,
`FrontAPI\Api::cashout_check` / `cashout_get`; лимиты `system_limit` типов
9/10/11 одинаковы на деве и проде): `actual` = произведение текущих кэфов
ног из `feed_bridge`; `ratio = round(odds × (100 − 10 %) / (100 × actual), 2)`;
сумма выкупа `floor(stake × ratio)`. Выкуп недоступен, если хоть одна нога:
событие не открыто (`events.status ≠ 1`) или снято, маркет закрыт или снят,
исход не открыт или снят, кэф < 1, маркет «точный счёт» (`CorrectScore`; в
Спорте запрещён по видам спорта настройкой `market_cashout_disabled_types`
после эксплойта 09.2026); а также при `ratio > 5` (потолок). Котировка
приходит вместе со списком ставок (`bet.cashout {enabled, price, reason}`),
кнопка «Кешаут ~сумма» — слева внизу карточки открытой ставки; по клику —
подтверждение с суммой «≈», которая пересчитывается каждые 2 с (как в
Спорте: «сумма выкупа меняется со временем»), затем выкуп с серверной
задержкой 5 с и выплатой по котировке на момент выкупа. Ставка получает
статус «Выкуплена» и уходит в «Архив», сумма — в баланс. Не перенесено из
Спорта: проверка вилок (в `feed_bridge` нет флага `fork`), порог верификации
крупных выкупов (`win_threshold`, 100 000 HTG → ручное подтверждение),
блокировка кешаута отдельному пользователю (`block_cashout`).

Правая колонка — две вкладки: **«Купон»** (как в моке) и **«Мои ставки»** (в
кружке на вкладке — число открытых ставок) —
последние 50 ставок пользователя из кошелька, внутри подвкладки **«Текущие»**
(открытые) и **«Архив»** (рассчитанные и отменённые) со счётчиками, выбор
запоминается в `localStorage`, принятая ставка открывает «Текущие»; новые
сверху: статус
(открыта / выиграла / проиграла / возврат / отменена / выкуплена), время, ноги с кэфами,
сумма, общий кэф, возможный выигрыш или выплата; у открытых ставок под ногой
идёт текущий период и счёт матча, обновляемые на месте. Выбранная вкладка
запоминается в `localStorage`; клик по кэфу открывает купон, принятая ставка
переключает на «Мои ставки».

**Когда рассчитается ставка** — справа под линией открытой ставки «Расчёт ≈
через N мин» (обратный отсчёт ведёт страница, точность минута, по WS ничего не
шлётся), после срока — «Рассчитывается…»; у рассчитанных — время расчёта.
Момент расчёта (`bet.eta`, unix) считает сборщик раз в минуту (`leg_eta` в
`health/collect.py`) с запасом, для экспресса — по самой поздней ноге:

| Вид спорта | Prematch | Live |
|---|---|---|
| футбол | старт + 125 мин | по таймеру фида: остаток тайма + 5 мин добавленного (+ 15 мин перерыва и второй тайм, если идёт первый); маркеты 1-го тайма — до конца тайма |
| хоккей | старт + 175 мин | текущий период целиком (≈35 реальных мин) + оставшиеся периоды с перерывами по 17 мин |
| баскетбол | старт + 140 мин | текущая четверть целиком (≈28 мин) + оставшиеся, большой перерыв 15 мин |
| гандбол | старт + 135 мин | текущий тайм целиком (≈35 мин) + второй тайм и перерыв 15 мин |
| остальные | — | — (часов нет, разброс по сетам велик) |

Ко всему прибавляется 10 минут на расчёт фидом. Константы взяты из замера по
`feed_bridge` 05–08.09.2026 (старт → расчёт основных маркетов, медиана / 90 %:
футбол 119/144, хоккей 142/172, баскетбол 111/138, гандбол 108/132 мин; сам
фид рассчитывает исходы через 3–10 минут после конца матча).

Ограничения эмуляции: без авторизации (пользователь — параметр URL), без
лимитов на события/маркеты и без лимитов выплат. Для реальной интеграции
кошелёк партнёра будет вызываться нашим бэкендом ставок по Platform API, как
у Borlette.

**Контракт `window.SB`** тот же, что у `data/mock-events.js` (см.
`sportsbook-iframe-designs/shared/CONTRACT.md`): `SPORTS`, `LEAGUES`, `EVENTS`
с `mainMarkets` (три главных маркета) и `allMarketsCache`, `Market`/`Selection`,
купон в `localStorage`, `indexSelections()`. Отличия: id исходов строковые
(`"<eventId>|<marketHash>|<outcomeHash>"`), добавлен `SB.visibleEvents()` и
`SB.live.*` (инициализация, счёт по периодам).

**Откуда данные** (адаптер `live-data.js`):

| Что | Источник | Обновление |
|---|---|---|
| виды спорта, live + prematch на 12 ч, названия, счёт с таймером и версией события `dv`, **главные маркеты** каждого события (`main` — по слотам вида спорта из `mmain`, см. ниже) | `/feed-health/catalog.json` — пишет `health/collect.py` | раз в минуту |
| все маркеты события | REST `api/snapshot.php?id=<feed_id>` — из `feed_bridge` по запросу для любого события (PHP, пользователь БД `sport_ro` только на чтение, доступы `/var/lib/sport-live/db.json`); запасной вариант — статический `/feed-health/snap/{eventId}.json` сборщика (только live и ближайший час, флаг `snap`) | по запросу (REST) / раз в минуту (статика) |
| дельты | Centrifugo: `sport:{sportId}` всех видов спорта, `event:{eventId}` live-событий (до 90) и hot-prematch | сразу после commit бриджа |

Главная: каталог → `SBInit()` рендерит всё движком мока; дельты обновляют
кэфы, доступность, счёт и период на месте (без перерисовки таблицы, с
подсветкой роста/падения кэфа); смена состава live (стартовал, завершился,
пропал из фида) перерисовывает секции. Перерисовка секций, сайдбара и
купона идёт только при реальном изменении их содержимого (подпись состава:
события, порядок, hot, главные маркеты; для купона — исходы, кэфы, ставка):
дельты завершённых и невидимых событий DOM не трогают, поэтому строки под
курсором не мигают, а поле ставки не теряет фокус. На странице события то же:
шапка (лига, команды) строится один раз, счёт и период правятся на месте;
сетка маркетов сверяется по ключам блоков и id линий (новые вставляются,
исчезнувшие убираются, порядок — перестановкой узлов, состав исходов линии —
заменой её содержимого), кэфы, доступность и признак «закрыт» правятся на
месте. Полная пересборка сетки — только при первом рендере.

**Панель фильтра над маркетами (как у 1xBet)**: слева выбор периода («Все
периоды», «Основное время», «1 Тайм», «2 сет» …), затем вкладки «Все / Тотал /
Фора / Популярные» со счётчиками линий в выбранном периоде, справа поиск по
названию маркета и подписям исходов и кнопка «свернуть / развернуть все».
«Тотал» — типы с `Total` в коде (в том числе индивидуальные и угловые),
«Фора» — с `Handicap`, «Популярные» — первые 16 пар (тип, период) из порядка
маркетов админки `cfg:m` для вида спорта (без `cfg:m` — основные типы
основного времени). Панель липкая под шапкой; фильтр применяется к той же
сверке DOM, без полной пересборки.

**Сетка маркетов события — компактная, как в 1xBet**: линии одного типа и
периода собраны в один блок («Фора», «Тотал», «Двойной шанс · 1-й тайм») с
заголовком, числом линий и сворачиванием по клику; каждая линия — строка из
ячеек «подпись слева, кэф справа» (2 или 3 колонки по числу исходов, у
многоисходных маркетов вроде точного счёта — 2 колонки с переносом); периоды
(1-й тайм, сет 2 …) отделены полосой. Порядок блоков — по `cfg:m`, линий
внутри — по значению линии. Страница события: каталог (имена) +
снимок → `allMarketsCache`; дельты маркетов/исходов обновляют карточки.

**Подписи маркетов, исходов и периодов — из словарей фронта Спорта.** Фид
отдаёт названия кодами (`Win1AndDraw`, `BothToScoreAndWin1`, `Half1`) на всех
языках одинаково; переводы кодов ведёт команда Спорта в
`betting/BackEnd/dict/frontend/{ln}.ini` (13 языков, секции
`frontapi.event.market.name` / `.outcome` / `.subperiod`, `frontapi.sport.name`),
Vue-фронт Спорта берёт их как `dict('event.market.outcome.' + код)`. Скрипт
`tools/export_dict.py` выгружает эти секции в `assets/dict/{ln}.json`
(ru, en, fr, ht; повторять при обновлении ini). Адаптер резолвит подпись по
цепочке: словарь → правила с значениями (`Б 2.5` / `М 2.5`, `Ф1 −1` / `Ф2 +1`,
счёт `2:0`, диапазон тотала `2–3`; в en `O`/`U`, `W1`/`W2`, в fr/ht — слова
из словаря) → свои дополнения для кодов, которых нет в словаре (десяток
исходов вроде `TwoAndMore`, маркетов вроде `DrawNoBet`, периодов `InningN`,
`Set6+`) → разбиение кода на слова. Покрытие фида словарём: маркеты 99 %,
периоды 99 %, исходы 82 % по объёму (остальное — составные коды с
значением, закрытые правилами).

**Языки страницы.** Интерфейс переведён на ru, en, es, pt
(`assets/js/i18n.js`: строки интерфейса, `SB_I18N.t(key, vars)`, статические
подписи разметки через `data-i18n*`); словари фида выгружены для ru, en, es,
pt, fr, ht. Язык берётся из `?ln=`, иначе из `localStorage`, иначе `ru`;
переключатель RU / EN / ES / PT в шапке пишет выбор в `localStorage` и
перезагружает страницу с `?ln=`, поэтому переходы между страницами язык
сохраняют. Для `fr` и `ht` переведены только подписи фида, интерфейс
английский. Формат чисел и дат — по локали языка (`ru-RU`, `en-GB`,
`es-ES`, `pt-BR`). Подписи исходов без сокращений, как у 1xBet: тотал «Более
2.5 / Менее 2.5» словами из словаря Спорта (en Over/Under, es Más/Menos, pt
Acima/Abaixo), фора «1 (+1) / 2 (−1)», победитель ru `П1 / X / П2`, en `W1 /
X / W2`, es и pt `1 / X / 2`; в заголовках лиг главной таблицы те же слова. Заголовок
линии: `Тотал 2.5`, `Фора −1`, с суффиксом периода (`· 1 Тайм`, `· 2 сет`).
Период в строке таблицы: футбол `2Т 67'`, теннис `Set 3, 4-2`, баскетбол
`Q3 8:42`, хоккей `2-й период 12'`.

**Главная таблица — как у 1xBet.** Перед каждой лигой заголовок «страна ·
турнир» с подписями колонок по исходам (`1 X 2 · Б Тотал М · Ф1 Фора Ф2 · +`);
набор колонок считается по событиям группы (`--gcols`), у события без
какого-то маркета — пустая ячейка, так что ячейки всех строк совпадают с
подписями. Строка события: две строки команд с логотипами, справа от названий
счёт по колонкам (итог жёлтым и периоды серым, как у 1xBet), под командами
статус (`2Т 67'` с пульсирующей точкой, у prematch — дата и время); ячейки
только с кэфами, значение линии тотала/форы между ячейками, в конце «+N»
остальных маркетов. Счёт, статус и «+N» обновляются на месте.

**Порядок видов спорта, лиг и маркетов — из админки Спорта.** Приоритеты
витрины ведёт спортаналитик в разделе «Сортировка» админки (`_repos/betting/BackEnd`,
`app/plugin/admin/controller/sort/*`); они лежат в том же Redis фида ключами
`cfg:*`, и сборщик каталога забирает их точечным `MGET` по хэшам категорий и
турниров событий каталога (без `SCAN`):

| Ключ | Что | Куда в каталоге |
|---|---|---|
| `cfg:s:{sport}` `{order, excl}` | порядок / исключение вида спорта | `sports[].o`, `sports[].x` |
| `cfg:c:{sport}:{catHash}` `{order, excl}` | порядок / исключение страны (категории) | `events[].co`, `events[].x` |
| `cfg:t:{sport}:{catHash}:{trnHash}` `{order, excl}` | порядок / исключение турнира; новым турнирам админка даёт `999999` (хвост) | `events[].to`, `events[].x` |
| `cfg:tl:{sport}` `{order:[trnHash…]}` | порядок турниров в live | `events[].lp` (позиция или `null`) |
| `cfg:th:{sport}` `{order:[trnHash…]}` | hot-турниры | `events[].hot` |
| `cfg:m:{sport}` `[{m:type, p:period}]` | порядок маркетов витрины | `mcfg[sport]` |
| `cfg:me:{sport}` `[{m:type, p:period}]` | маркеты, исключённые с витрины | `mexcl[sport]` |

**Порядок из админки берём, исключения — нет** (16.09.2026). Флаги `excl`
(`sports[].x`, `events[].x`) каталог по-прежнему несёт, но партнёрская витрина по
ним ничего не прячет: переключатель `SHOW_ADMIN_EXCLUDED` в
`assets/js/live-data.js` (рядом с `pickHot`). Причина: Пижама отбирает, что
принимать, по своей линии, а партнёру продаётся полнота фида — что из неё
выставлять, решает он сам. На 16.09.2026 исключения закрывали 311 событий
каталога из 723 (43 %), причём ни один вид спорта целиком не исключён — гасятся
страны и турниры. Открывшееся — это в основном мелкий реальный спорт (ITF, UTR,
ATP Challenger, ITTF, вторые лиги, товарищеские) и, отдельной группой, виртуальные
и повторные события (`Virtual football`, `Virtual basketball`, `Virtual Tennis`,
`Replays · VI. …`). Чтобы вернуть набор Пижамы — поставить `false`.

Ранг события. **В лайве — как в основном Спорте** (`betsportwss`,
`get_events_for_live` + `getLive2SportEvents`): сначала турниры из `cfg:tl` в
порядке этого списка, затем все прочие просто по времени начала, а лига встаёт
туда, где начался её самый ранний матч (группировка по лигам идёт уже после
сортировки).

При равном времени начала у основного Спорта решает порядок обхода дерева в
памяти WS: категории и турниры — в порядке добавления (ключи-хэши, обход
объекта), события внутри турнира — по возрастанию id (числовые ключи объекта
обходятся по возрастанию). Порядок событий внутри турнира воспроизведён точно —
по id. Порядок добавления турниров воспроизвести нельзя: это история процесса, а
не данные фида (рестарт WS её меняет); вместо него берутся веса стран и турниров
из админки — детерминированы и не «прыгают» между перерисовками. Практический
итог сверки 13.09.2026 на ночном слейте: порядок событий внутри лиг совпал
полностью, порядок лиг — везде, кроме одной пары турниров одной страны с
одинаковой минутой начала и без весов в админке.

**В расписании**: страна → турнир из админки → хвост без рангов
(лиги с большим числом маркетов выше, затем по имени) → внутри лиги по времени
начала. Виды спорта в сайдбаре — в порядке
`cfg:s`, виды без ранга — по числу событий. Исключённые в админке вид спорта, страна или
турнир не показываются. На странице события маркеты идут в порядке `cfg:m`
(пара тип + период; тип без точного периода — после ранжированных пар),
исключённые пары из `cfg:me` не показываются. Недоступный маркет на страницу
события не выводится вовсе: он либо закрыт у поставщика, либо все его исходы
погашены, и поставить по нему нельзя. Так делал спорт старой Пижамы
(`sport/Betting`, `V-MarketsBrowser.groupedMarkets`), и на то есть причина:
21.09.2026 в лайве закрыты 3232 маркета из 4427, а на отдельных матчах 286 из
290 — игрок листал десять экранов серых блоков. Маркет, закрывшийся у него на
глазах, ещё 20 секунд держится на месте серым и только потом уходит: замер тех
же суток дал 103 закрытия в минуту при медиане закрытого состояния 17 секунд,
и мгновенное скрытие дёргало бы страницу под пальцем. Если доступных маркетов
не осталось, вместо пустоты выводится строка о приостановке ставок. Отдельный
погашенный исход внутри рабочего маркета остаётся видимым и серым, а в колонках
таблицы лайва и линии закрытая ячейка тоже остаётся на месте — там ширина
колонок общая на лигу. Семантика флагов та же, что у WS-моста Спорта
`betsportwss` (`isExcluded`, `markets_excludes`). Хэши категорий и турниров в
`feed_bridge` (`categories.feed_hash`, `tournaments.feed_hash`) совпадают с
хэшами в ключах `cfg:*`, поэтому джойн прямой. Второй профиль сортировки
админки (`cfg_dm:*`) не используется. Партнёрский слой переопределения этих
весов (свой порядок лиг у партнёра) — отдельная задача на будущее, поверх
`cfg:*`, не правкой самих ключей.

**Лайв и линия — разные страницы**, как у букмекеров: `index.html` (лайв) и
`line.html` (линия, prematch). У каждой свой URL и своя запись в истории
браузера, переход между ними — кросс-документный View Transition. Переключатель
со счётчиками событий — над списком видов спорта в сайдбаре; выбранный вид
спорта переносится на вторую страницу через хэш (`#sport=s1`), лига не
переносится — на другой странице состав лиг другой.

**Сайдбар** (как в 1xBet): «Все» + виды спорта со счётчиками событий **текущей
страницы**; клик по виду спорта фильтрует список и раскрывает его лиги, клик по
лиге фильтрует до неё, повторный клик по раскрытому виду спорта сворачивает
список. Фильтр виден в адресной строке (`#sport=s1&league=12`) и переживает
перезагрузку; если после переключения лайв↔линия выбранному фильтру нечего
показать, он снимается. Лиги идут в том же порядке, что и в таблице (первое
появление в отсортированном списке событий), и подписаны как в заголовках
таблицы — «страна · турнир». На узком экране (≤760 px) сайдбар остаётся
горизонтальной лентой видов спорта: лиги в ней не показываются, переключатель
лайв/линия держится у левого края. На странице события сайдбар подсвечивает вид
спорта и лигу матча, а его ссылки ведут на ту страницу списка, откуда матч.

**Телефон** (ширина до 760 px, вариант M2, выбран владельцем из четырёх): навигация
внизу экрана, как в приложениях букмекеров — «Лайв», «Линия», «Купон» со
счётчиком выбранных исходов и «Ставки» (`#sb-mnav`, на десктопе скрыта). Она же
открывает купон шторкой снизу и заменяет прежнюю плавающую кнопку и верхний
переключатель лайв/линия — в сайдбаре на телефоне остаётся только липкая лента
видов спорта (лиги на этой ширине не показываются). Строка матча компактная:
слева команды, справа кэфы главного маркета и «+N» остальных; тотал и фора
скрыты, поэтому таблица влезает в экран без горизонтальной прокрутки. Hot
events — горизонтальная карусель со свайпом.

**Колонки кэфов в таблице — набор главных маркетов вида спорта из админки Спорта.**
Раздел «Сортировка / Маркеты» задаёт порядок маркетов витрины (`cfg:m:{sport}`,
пары «тип + период»); первые три пары этого порядка и есть колонки таблицы.
Ровно так работает основной сайт Спорта: `betsportwss` отдаёт фронту главные
маркеты по первым `mcount` записям того же порядка (`model.js mainMarkets`), а
live-список запрашивает `mcount = 3` (`client.js`). Поэтому наборы совпадают:
футбол — победитель, двойной шанс, фора; хоккей — победитель, победитель без
ничьей, двойной шанс; теннис — победитель, фора по геймам, тотал геймов;
баскетбол — победитель с овертаймом, победитель основного времени, фора.
Исключённые пары (`cfg:me`) пропускаются, как и пары с числом исходов не 2–3
(точный счёт в колонку не помещается). Набор кладётся в каталог полем `mmain`
(`sportId → [{t, p, n, oc}]`), маркеты события — массивом `main` в том же
порядке слотов; если у пары несколько линий (тотал 2.5 и 3.5, фора ±1), в
таблицу идёт самая сбалансированная открытая. Значение линии показывается так же,
как в основном Спорте: у тотала оно общее для обеих сторон и стоит колонкой между
кэфами, у форы у каждой стороны своё — тогда значение идёт внутрь ячейки («−1 2.03»),
а столбцы подписаны «Фора 1» и «Фора 2». Если маркета у события нет вовсе, вместо
пустых плашек показывается «Ещё» во всю ширину группы (клик по строке открывает
страницу события со всеми маркетами); если маркета нет ни у одного события лиги,
«Ещё» встаёт и в шапку лиги вместо подписей столбцов — так же, как в основном Спорте. Последний удачно прочитанный набор сборщик хранит в
`/var/lib/feed-health/main_markets.json` и берёт оттуда, если Redis фида не
ответил.

**Hot events**: события hot-турниров из админки (`cfg:th`) — до 6 live в
порядке лиг и до 3 ближайших prematch; если hot-турниров в
текущем составе меньше, недостающие места добираются в порядке лиг (live) и
prematch на ближайшие 3 часа в том же порядке. Карточка: лига и метка
LIVE/PRE, две команды столбцами — логотип 48 px и название под ним (до двух
строк), между ними счёт и период (live) или «vs» и время начала, внизу три
кэфа главного маркета; счёт и период обновляются по WS на месте.

**Что не показывается** (как на live-странице Пижамы): завершённые матчи
(`status 3`) снимаются сразу; исключённые в админке виды спорта, страны и
турниры (`cfg:*.excl`); матчи без главных маркетов не выводятся, пока
каталог не отдаст маркеты (событие, пришедшее только по WS, ждёт следующего
обновления каталога, до минуты); live-события вне каталога без WS-дельт
10 минут считаются зависшими и убираются.

**Свежесть данных на странице.** Каталог (раз в минуту) и WS-дельты идут разными путями, поэтому
на каждое поле решается, что новее. Состояние события (счёт, стадия, статус) сравнивается по паре
версий фида `(dv, sdv)`: каталог применяется, если он не старше пришедшей дельты — так потерянная
дельта лечится за минуту. Кэфы главных маркетов сравниваются по времени: момент WS-обновления
пишется в **серверной** шкале (поправка часов берётся из заголовка `Date` ответа каталога), иначе
у браузера со спешащими часами кэф, обновлённый по WS, навсегда считался бы свежее каталога.

**Переходы между страницами**: кросс-документный View Transition
(`@view-transition { navigation: auto }`, Chrome 126+ / Safari 18.2+) — шапка
и колонка купона остаются на месте, контент сменяется с затуханием; в других
браузерах контент просто появляется с коротким затуханием при загрузке. До
прихода каталога и снимка на месте шапки события, маркетов и live-таблицы —
мерцающий скелет. Кнопка купона и подложка мобильной шторки на десктопе
скрыты базовым правилом (без него нестилизованная кнопка была видна у левого
края, пока страница короткая).

**Фон**: ровный `--bg` без градиентов (радиальный градиент мока и градиент
подложки карточек Hot events убраны 10.09), поверх — водяной знак бренда:
вертикальная надпись PARYAJPAM вдоль правого края и SPORT рядом
(псевдоэлементы `body::before/::after`, `position: fixed`, `z-index: -1`,
прозрачность ≈5 %), закреплён при прокрутке, на экранах уже 760 px скрыт.
Выбран владельцем из семи вариантов (пиктограммы видов спорта, точечная
сетка, контурные линии, гексагональная сетка, футбольное поле, орбиты).

## Встраивание (витрина продуктов и партнёры)

Страница рассчитана на работу в `<iframe>` на чужом домене: заголовков, запрещающих
встраивание, на `/sport-live/` нет, наружу из iframe страница не уходит — вся
навигация внутренняя. Встраивающая сторона управляет двумя параметрами URL:

| Параметр | Что задаёт | Поведение |
|---|---|---|
| `?ln=` | язык (`ru`, `en`, `es`, `pt`; для `fr`/`ht` переведены только подписи фида) | параметр → `localStorage` → `ru` |
| `?user=` | пользователь эмулированного кошелька | параметр → `localStorage` → `42` |

Оба параметра запоминаются в `localStorage` и переносятся во все внутренние переходы
(событие, возврат к списку, выбор вида спорта), поэтому клик по матчу не сбрасывает
ни язык, ни демо-баланс. Значение `user` витрина заводит своё на каждого посетителя,
так что демо-балансы разных посетителей не пересекаются.

Пример: B2B-витрина `https://gem.x1b.site/product-showcase/` (репозиторий
`paryajpam/product-showcase`) в блоке «Спортивный фид» открывает
`/sport-live/?ln=<язык витрины>&user=<id посетителя>` в модальном окне поверх
страницы — тем же механизмом, что и живой запуск Borlette.

## Устойчивость демонстрации

На живом фиде сами собой случаются ситуации, в которых страница раньше просто
«замирала», а на показе это выглядело как поломка. Теперь каждая объясняет себя.

**Полоса состояния** под шапкой (`#sb-alert`) показывает ОДНУ причину — самую важную
из случившихся:

| Причина | Как определяется | Что видно |
|---|---|---|
| Нет связи с сервером котировок | состояние соединения Centrifugo не `ok` дольше 8 с | красная полоса «цены не обновляются, переподключаемся» |
| Линия отстала | возраст `catalog.json` больше 3 минут (собирается раз в минуту) либо последняя загрузка не удалась | жёлтая полоса «линия обновлялась N мин назад» |
| Приём ставок закрыт гейтом | `gate.open=false` в ответе `api/wallet.php` (файл пишет `feedbridge/gate.py`) | жёлтая полоса «ставки временно не принимаются»; в купоне — та же причина, кнопка недоступна |

Про обрыв связи важно: `centrifuge-js` переподключается сам и при потере связи висит в
состоянии `connecting`, а не `disconnected` — поэтому «нет связи» считается по
длительности, а не по событию. Возраст каталога считается по часам сервера
(`SRV_SKEW` — поправка на расхождение часов, иначе телефон с убежавшим временем
показывал бы ложное отставание).

**Пустой лайв** (ночь по Гаити, окно между турами) вместо пустой таблицы показывает
объяснение, время ближайшего матча и кнопку «Смотреть линию», а под ней — ближайшие
матчи из каталога. В список попадают только те, что ещё
не начались: в каталоге встречаются «зависшие» события с давно прошедшим стартом.

Проверка — `tools/resilience-test.js` (Playwright, запускается на тестовом сервере):
шесть сценариев, каждый подменяет ответ сервера в браузере, живой стенд не трогается —
базовый, отставший каталог, обрыв WS, восстановление связи, закрытый гейт и отсутствие
лайва (каталог переводится в предматч, WS отключается, иначе дельты вернут матчам
лайв). Отчёт и скриншоты — в каталоге запуска.

## Темы оформления

Пять тем: две наши и три перенесённые с витрины дизайн-концептов. Переключатель —
выпадающий список в шапке рядом с выбором языка; выбор запоминается в `localStorage`
(`sportsbook-live-theme`) и переносится по переходам между страницами.

| Тема | Значение `data-theme` | Характер |
|---|---|---|
| Тёмная | (атрибут снят) | палитра портала, по умолчанию |
| Светлая | `light` | она же на светлом фоне |
| Классика | `classic` | графитовые панели, зелёная шапка, жёлтый акцент — в духе bet365 |
| Пульс | `pulse` | тёмно-синие панели, мятный акцент — в духе Stake |
| Рынок | `market` | светлая витрина, жёлтая шапка, тёмный текст — в духе Betfair |

Три последние взяты с `paryajpam-design-concepts.kompotik797.chatgpt.site` (концепты
01 CLASSIC, 02 PULSE, 03 MARKET). Перенесён только цвет: разметка, плотность и состав
экранов остались наши. Значения не подбирались на глаз — у концептов каждая тема задана
девятью переменными (`--bg`, `--panel`, `--raised`, `--fg`, `--muted`, `--line`,
`--accent`, `--action`, `--on-action`), они и легли в наши: `panel` → `--table`,
`raised` → `--table-2`, `line` → `--stroke`, `fg` → `--mainText`, `muted` →
`--secondText`, `accent` → `--brand`.

Встраивающая сторона задаёт тему параметром **`?theme=light|dark|classic|pulse|market`** —
так витрина `product-showcase` открывает линию в своей теме (у неё тот же переключатель).
Тема проставляется инлайн-скриптом в `<head>` до первой отрисовки, иначе в светлой теме
мигает тёмный фон.

Вместе с `data-theme` скрипт ставит на `<html>` атрибут **`data-lum`** (`light`/`dark`) —
по нему выбирается набор иконок. Без него светлый «Рынок» получил бы белые иконки тёмной
темы: раньше набор выбирался по имени темы `light`, а тем со светлым фоном стало две.

Цвет шапки в концептах живёт отдельно от фона страницы (зелёная у «Классики», жёлтая у
«Рынка»), у нас же шапка красилась полупрозрачным `--rgb-bg`. Поэтому добавлены две
переменные: `--header-bg` и `--logo-grad`; в двух старых темах они дают ровно прежний вид.
Логотип на жёлтой шапке «Рынка» золотом не читается, поэтому градиент у него там свой,
тёмный.

На экранах уже 520 px список показывает только стрелку (`font-size: 0`): с названием
«Классика» он занимал 90 px против 28 px у прежней кнопки и выталкивал баланс за правый
край. Полные названия видны, когда список раскрыт, — их рисует система.

Реализация — только CSS-переменные: базовая палитра в `:root`, остальные в
`:root[data-theme="..."]`. Структурные цвета записаны тройками компонент
(`--rgb-bg`, `--rgb-table`, `--rgb-stroke`, `--rgb-fg`, `--rgb-main`, `--rgb-brand`),
чтобы полупрозрачные подложки (`rgba(var(--rgb-table), .7)`) работали в обеих темах.
Две роли золота разведены: `--onBrand` — текст на золотой заливке (тёмный в обеих
темах), `--brandInk` — золото как цвет текста (на белом чистое `#ffd100` нечитаемо,
поэтому в светлой теме это тёмная охра `#8A6400`).

## Пиктограммы

До 13.09.2026 виды спорта в сайдбаре и строках лиг, вкладки нижней навигации телефона,
заголовки секций («Hot events», «LIVE сейчас», «Расписание»), пустой купон и список
ставок, замок на закрытом кэфе, предупреждение о недоступном исходе и кнопка темы
показывались эмодзи. Их рисует система игрока: на iPhone, Android и Windows они
выглядят по-разному и выпадают из палитры страницы. Теперь это два набора
PNG-пиктограмм, сгенерированных Nano Banana (`gemini-2.5-flash-image`) в стиле сайта,
отдельно под каждую тему:

| Набор | Палитра | Где лежит |
|---|---|---|
| тёмный | золото `#FFB62F`, толстая обводка и внутренние детали navy `#0A1A2F` | `assets/icons/dark/` |
| светлый | сплошной navy `#10263A` одним цветом, детали — просветы фона | `assets/icons/light/` |

Стили выбраны владельцем 16.09.2026 из десяти вариантов, отрисованных на одном сюжете
(футбольный мяч) под обе темы. Бирюзы, которая была в первом наборе, нет ни в одном знаке.
Каждый набор рисуется своим промптом с нуля: первая версия получала светлый набор
перекрашиванием тёмного (image-to-image), и на знаках оставались тёмные фрагменты
исходника. Состав — 12 видов
спорта фида (`s<id>`), запасная «медаль» (`sport`) для вида спорта без своей картинки,
«Все» (`all`) и служебные `live`, `line`, `coupon`, `bets`, `hot`, `lock`, `sun`, `moon`,

navy-вариант. Замок и солнце/луна ставятся из `main.css` псевдоэлементами.

Готовый набор проверяет `tools/icons/check_icons.py`: ищет заметную бирюзу, нарушение

сохранила — она не часть продукта.

## Мобильный вид

Телефон — основной экран показа (витрину открывают со смартфона), поэтому вёрстка
доведена отдельно и проверяется автоматически.

- **Разделы** переключает нижняя панель (`.sb-mnav`): «Лайв», «Линия», «Купон»,
  «Ставки». Купон и «Мои ставки» открываются нижним листом поверх страницы,
  плавающая кнопка купона на телефоне не используется.
- **Строка матча**: счёт по периодам не показывается (только итог) — освободившееся
  место отдано названиям команд; ячейки кэфов 44 px, «+N» 26 px. На 360 px имя
  команды получает ~100 px вместо прежних 56 px, на 390 px — ~131 px.
- **Страница события**: лента видов спорта скрыта (`body.sb-page-event`), шапка
  компактная (логотипы 34 px, команды в строку), панель фильтра маркетов — две
  строки вместо трёх. Маркеты попадают в первый экран.
- **Тап-таргеты** не мельче 32 px: кэфы в сетке маркетов 40 px, вкладки фильтра и
  «Текущие / Архив» 34 px, удаление позиции из купона 32×32.
- **Ширина**: на 360 px страница укладывается в экран без горизонтальной прокрутки и
  без «ужимания» страницы браузером (shrink-to-fit) — за этим следит верхняя строка
  шапки, самая плотная на узком экране.

Проверка — `tools/mobile-audit.js` (Playwright). Гоняется **на тестовом сервере**
`46.62.223.10`, где стоят playwright и chromium (`/opt/pw-admin/node_modules`):

```bash
ssh root@46.62.223.10
cd /opt/sl-mobile && OUT=/opt/sl-mobile/shots node mobile-audit.js
```

Скрипт открывает лайв, линию, событие, купон и «Мои ставки» в 390×844 и 360×800,
снимает скриншоты и отчёт `report.json`: горизонтальное переполнение, тап-таргеты
мельче 32 px, обрезанный текст, мелкий шрифт, ошибки консоли.

## Ограничения прототипа

- Настоящего бэкенда ставок нет: приём ставок, баланс и расчёт выигрышей
  работают на эмулированном кошельке партнёра (`api/wallet.php`), авторизации
  нет — пользователь задаётся параметром `?user=` (см. «Встраивание»).
- Логотипы команд — из репо `betting/team_logo` (клон `/opt/team_logo` на *10,
  раздача `https://gem.x1b.site/team-logo/<d>/<id>.png`): сборщик каталога
  резолвит имена хозяев/гостей через `team_logo.py` (`attach_logos`, кэш
  имя → ссылка в `/var/lib/feed-health/logo_cache.json`, промахи тоже
  кэшируются — удалить файл для пересчёта) и кладёт в события `lh`/`la`;
  страница рисует картинку поверх монограммы, монограмма остаётся, если
  логотипа нет или он не загрузился. Покрытие зависит от лиг дня: у
  топ-лиг почти полное, у мелких — низкое (08.09.2026: 216 из 523 событий
  каталога с логотипом хозяев).
- Новый live-матч без снимка в списке показывается по WS-дельте события; его
  главные маркеты появятся с обновлением каталога (до минуты). Страница события
  открывается для любого события из БД бриджа (снимок по REST), даже если
  каталог его не отдал — имена и лига берутся из снимка.
- Расписание — вся линия prematch из каталога (21.09.2026 — 1442 события);
  кэфы в них обновляются вместе с каталогом (подписки только на live и hot).
  Список рисуется порциями по 120 событий с дорисовкой по скроллу: разом это
  1600 строк и 51 тыс. узлов, из-за которых страница дёргалась на каждом пуше.
